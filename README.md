# ระบบวางบิลร้านไวนิล (Vinyl Shop Billing System)

ระบบจัดการงานรับจ้างพิมพ์ไวนิล ครอบคลุมตั้งแต่ รับออเดอร์ → เสนอราคา → ส่งของ → วางบิล → รับชำระเงิน → ออกใบเสร็จ พร้อมระบบตรวจสอบย้อนหลัง (Audit Trail) ทุกการกระทำ

**Stack:** Google Apps Script (.gs) + Vanilla JS + Tailwind CSS + SweetAlert2 + Google Sheets (DB) + GitHub (clasp CI/CD)
**ภาษาในระบบ:** ไทย 100% | **Timezone:** Asia/Bangkok | **สกุลเงิน:** THB

---

## ฟีเจอร์หลัก

- บันทึกรายการสั่งจ้างไวนิล (แยกราคาค้าส่ง / ค้าปลีก)
- บันทึกรายการวางบิล
- บันทึกรายการรับชำระเงิน (เงินสด / โอน / เช็ค / บัตร / QR)
- ออกใบเสร็จ — พิมพ์ซ้ำได้ไม่จำกัด
- บันทึกการทำงานหลังบ้านทั้งหมดเพื่อตรวจสอบภายหลัง (Audit Trail)
- การยกเลิกแบบ Cascade — VOID ทั้งสายเอกสารในทรานแซกชันเดียว

## วิธีติดตั้ง (Installation)

### ข้อกำหนดเบื้องต้น

- บัญชี Google (Gmail) ที่มีสิทธิ์เข้าถึง Google Sheets, Google Drive
- Node.js (แนะนำ version 18 ขึ้นไป)
- Google Chrome หรือเบราว์เซอร์ที่เปิด Web App ได้

### ขั้นตอนที่ 1 — ติดตั้งเครื่องมือ clasp

```bash
npm install -g @google/clasp
```

ล็อกอินด้วยบัญชี Google:

```bash
clasp login
```

### ขั้นตอนที่ 2 — Clone โปรเจกต์

```bash
git clone https://github.com/itman-ncc/pro-nara.git
cd pro-nara
```

### ขั้นตอนที่ 3 — ตั้งค่า Spreadsheet ฐานข้อมูล

1. สร้าง Google Spreadsheet ใหม่ (หรือใช้ได้กับไฟล์ที่มีอยู่เดิม)
2. คัดลอก `SheetID` ปัจจุบัน (ส่วนหลัง `/d/` ใน URL)
3. เปิดไฟล์ `src/Config.gs` แล้วแก้ไขค่าคงที่ `SPREADSHEET_ID`

### ขั้นตอนที่ 4 — ติดตั้งไฟล์สคริปต์

```bash
cd pro-nara
clasp push
```

### ขั้นตอนที่ 5 — รัน Setup

1. เปิดโปรเจกต์ใน Apps Script ผ่าน `clasp open`
2. เลือกฟังก์ชัน `setupSystem` แล้วกด Run
3. ให้สิทธิ์ (Authorization) เมื่อระบบขอ
4. ระบบจะสร้างชีตทั้งหมดและ seed ข้อมูลตัวอย่างให้อัตโนมัติ

### ขั้นตอนที่ 6 — Deploy เป็น Web App

```bash
clasp deploy --description "production"
```

เปิด Web App ผ่าน URL ที่แสดงผล (execute as: USER_DEPLOYING / access: ANYONE_ANONYMOUS)

## วิธีใช้งาน

1. **Dashboard** — ดูยอดขายเดือนนี้, ลูกหนี้ค้างชำระแยกอายุหนี้, งานค้างส่ง
2. **ใบสั่งจ้าง** — สร้างใบสั่งจ้างไวนิล กรอกรายการสินค้า ระบบคำนวณพื้นที่ตร.ม. และยอดเงินอัตโนมัติ
3. **วางบิล** — เลือกลูกค้า → เลือกงานที่ยังไม่วางบิล → รวมเป็นบิลเดียว
4. **รับชำระเงิน** — เลือกบิลค้าง → เลือกวิธีชำระ (เงินสด/โอน/เช็ค/บัตร/QR) → ออกใบเสร็จทันที
5. **ตรวจสอบย้อนหลัง** — ค้นหาประวัติการทำงานของทุกผู้ใช้ ทุกเอกสาร

## กฎธุรกิจสำคัญ (Business Rules)

### RULE-01: จุดล็อกเอกสาร
ก่อนออกใบเสร็จ = แก้ไขได้ | หลังออกใบเสร็จ = แก้ไขไม่ได้ ทำได้แค่ยกเลิก
ตัดสินจากเงื่อนไข: เอกสาร `doc_type IN ('RECEIPT','TAX_INVOICE')` และ `status = 'ACTIVE'` → ล็อกทันที

### RULE-02: ตารางสิทธิ์ตามสถานะ
`DRAFT`–`BILLED` = แก้ไขได้ (STAFF+) | `PARTIAL_PAID`–`PAID` = แก้ไขไม่ได้ (MANAGER+ เท่านั้นสำหรับยกเลิก) | `CANCELLED` = ไม่ทำอะไรได้

### RULE-03: การยกเลิกแบบ Cascade
ยกเลิกเอกสารใบใด → ระบบไล่ย้อนหา `order_id` ต้นทาง แล้ว VOID ทั้งสายในทรานแซกชันเดียว

### RULE-04: เหตุผลการยกเลิก
บังคับทุกครั้ง (ยกเว้น DRAFT) — ความยาวขั้นต่ำ 10 ตัวอักษร สูงสุด 300 ตัวอักษร

### RULE-05: ห้ามลบข้อมูล
ไม่มี hard delete — เปลี่ยนสถานะเป็น `VOID` / `CANCELLED` เท่านั้น

### RULE-06: Snapshot เอกสาร
ทุกครั้งที่ออกเอกสาร เก็บ `snapshot_json` ป้องกันการแก้ไขภายหลัง — พิมพ์ซ้ำได้ผลลัพธ์เหมือนเดิมเป๊ะ

### RULE-07: การพิมพ์ใบเสร็จ
พิมพ์ซ้ำได้ไม่จำกัด ครั้งที่ 1 = "ต้นฉบับ" ครั้งที่ 2+ = "สำเนา ครั้งที่ N" และบบันทึก AuditLog ทุกครั้ง เอกสาร VOID พิมพ์ได้แต่มีลายน้ำ "ยกเลิก"

## โครงสร้างฐานข้อมูล (Google Sheets)

| ชีต | คำอธิบาย |
|---|---|
| `Customers` | ลูกค้า |
| `Products` | สินค้า + ราคา 2 ระดับ (ขายปลีก/ขายส่ง) |
| `Orders` | ใบสั่งจ้าง |
| `OrderItems` | รายการในใบสั่งจ้าง |
| `Documents` | เอกสารทั้งหมด (QT/DO/BN/RC/TAX_INVOICE) |
| `Payments` | การรับชำระเงิน |
| `AuditLog` | Log การทำงาน (แยกไฟล์ต่างหาก) |
| `CancelLog` | ประวัติการยกเลิก |
| `Counters` | ตัวเลขลำดับเอกสาร |
| `Users` | ผู้ใช้ + สิทธิ์ |

**รูปแบบเลขที่เอกสาร:** `{PREFIX}-{YY พ.ศ. 2 หลัก}-{NNNN}` เช่น `OD-69-0125`

## การตั้งค่า CI/CD (GitHub Actions)

1. ไปที่ GitHub → Settings → Secrets → New repository secret
2. ตั้งชื่อ Secret: `CLASPRC_JSON`
3. เนื้อหา = เนื้อหาของไฟล์ `~/.clasprc.json` (หลัง `clasp login` แล้ว)
4. Push ไป branch `main` → Workflow จะ deploy อัตโนมัติ

## การสำรองข้อมูล (Backup)

ระบบสร้าง Time-driven Trigger สำรองไฟล์เข้าสู่ Drive ทุกวัน เวลา 02:00 ผ่าน `Backup.gs`
สามารถเปิด/ปิดได้ในฟังก์ชัน `setupBackupTrigger`
